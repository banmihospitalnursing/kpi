# KPI กลุ่มการพยาบาล — GitHub Pages + Firebase Realtime Database

เว็บแสดงผลและบันทึกตัวชี้วัดคุณภาพการพยาบาล ข้อมูลอัปเดตแบบเรียลไทม์ ล็อกอินด้วยบัญชี Google เฉพาะอีเมลที่ผู้ดูแลกำหนด

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าเว็บ |
| `styles.css` | หน้าตา / สี / ฟอนต์ |
| `app.js` | การทำงานทั้งหมด |
| `config.js` | **ไฟล์เดียวที่ต้องแก้** — ใส่ค่า Firebase |
| `database.rules.json` | กฎความปลอดภัยของฐานข้อมูล (วางใน Firebase Console) |

> ถ้า `config.js` ยังไม่มีค่า Firebase หน้าเว็บจะเปิดเป็น **โหมดตัวอย่าง** (ข้อมูลจำลอง) ใช้ดูหน้าตาและทดลองได้

---

## ขั้นที่ 1 — สร้างโปรเจกต์ Firebase (ครั้งเดียว ~10 นาที)

1. เข้า <https://console.firebase.google.com> → **Add project** → ตั้งชื่อ เช่น `nursing-kpi` (ปิด Google Analytics ได้)
2. **สร้างฐานข้อมูล**: เมนูซ้าย **Build → Realtime Database → Create Database**
   - Location: **Singapore (asia-southeast1)** (ใกล้ไทยที่สุด)
   - เลือก **Start in locked mode**
3. **เปิดล็อกอินด้วย Google**: **Build → Authentication → Get started → Sign-in method → Google → Enable** → ใส่อีเมลติดต่อ → Save
4. **อนุญาตโดเมน GitHub**: Authentication → **Settings → Authorized domains → Add domain** → ใส่ `ชื่อบัญชีgithub.github.io`
5. **วางกฎความปลอดภัย**: Realtime Database → แท็บ **Rules** → ลบของเดิม → วางเนื้อหาทั้งหมดจาก `database.rules.json` → **Publish**
6. **เอาค่า config**: ⚙️ **Project settings → General → Your apps → ไอคอน `</>` (Web)** → ตั้งชื่อแอป → Register
   → คัดลอกค่าใน `firebaseConfig` (apiKey, authDomain, databaseURL, …) มาวางใน `config.js`

> ⚠️ ตรวจว่ามี `databaseURL` ด้วย (หน้าตา `https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app`) ถ้าไม่มี คัดลอกจากหน้า Realtime Database ด้านบนตาราง

## ขั้นที่ 2 — ผู้ดูแลหลัก

ผู้ดูแลหลักคือ `banmihospital9@gmail.com` (ตั้งไว้ 2 ที่ ต้องตรงกัน)
- `config.js` → `superAdmins`
- `database.rules.json` → ค้นคำว่า `banmihospital9@gmail.com` (มีหลายจุด แทนที่ทั้งหมด) แล้ว Publish ใหม่

ผู้ดูแลหลักแก้ทุกอย่างได้เสมอ แม้ยังไม่มีผู้ใช้ในระบบ (ใช้ตั้งค่าครั้งแรก)

## ขั้นที่ 3 — ขึ้น GitHub Pages

1. สร้าง repository ใหม่ใน GitHub (Public) เช่น `nursing-kpi`
2. **Add file → Upload files** → อัปโหลดทั้ง 5 ไฟล์ → Commit
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**
4. รอ 1–2 นาที จะได้ลิงก์ `https://ชื่อบัญชี.github.io/nursing-kpi/`

## ขั้นที่ 4 — นำเข้าข้อมูลจาก Google Sheet (ครั้งแรก)

1. เปิดชีต preKPI → **ไฟล์ → ดาวน์โหลด → Microsoft Excel (.xlsx)**
2. เปิดเว็บ → ล็อกอินด้วยอีเมลผู้ดูแลหลัก → แท็บ **④ ตั้งค่า → นำเข้า / ส่งออก**
3. ลากไฟล์ .xlsx มาวาง → ตรวจตัวเลขสรุป (ควรได้ 7 กลุ่มงาน 16 หน่วยงาน 6 มิติ 691 ตัวชี้วัด) → **นำเข้าข้อมูล**

หลังจากนี้แก้ข้อมูลพื้นฐานผ่านหน้าเว็บได้เลย ไม่ต้องใช้ชีตอีก (นำเข้าซ้ำได้ ระบบจับคู่หน่วยงานตามชื่อ ผลงานเดิมไม่หาย)

## ขั้นที่ 5 — เพิ่มผู้ใช้ (อีเมลวอร์ด)

แท็บ **④ ตั้งค่า → ผู้ใช้งาน / สิทธิ์ → + เพิ่มผู้ใช้**

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| **admin** | ทุกอย่าง รวมหน้าตั้งค่า |
| **editor** | ลง / แก้ / ลบผลงาน **เฉพาะหน่วยงานที่ติ๊กไว้** + ดู Log |
| **viewer** | ดูแดชบอร์ดอย่างเดียว (เช่น ผู้บริหาร) |

อีเมลต้องเป็น **บัญชี Google** (Gmail หรือ Google Workspace ของโรงพยาบาล) — ถ้าวอร์ดใช้อีเมลอื่น สมัครบัญชี Google ด้วยอีเมลนั้นได้ที่ <https://accounts.google.com/signup> (เลือก "ใช้อีเมลปัจจุบันของฉันแทน")

## คำถามที่พบบ่อย

**เพิ่มวอร์ดใหม่ต้องทำอย่างไร?**
④ ตั้งค่า → หน่วยงาน / กลุ่มงาน → **+ เพิ่มหน่วยงาน** → ใส่ชื่อ + กลุ่มงาน → (ถ้าต้องการ) เลือก "คัดลอกชุดตัวชี้วัดจาก" วอร์ดที่คล้ายกัน + ตั้งรหัสนำหน้า เช่น `KVIP` → ระบบสร้าง `KVIP01 … KVIP44` ให้ → แล้วไปเพิ่มสิทธิ์อีเมลวอร์ดนั้นที่แท็บผู้ใช้งาน

**เพิ่มกลุ่มงานใหม่?** พิมพ์ชื่อกลุ่มใหม่ในช่อง "กลุ่มงาน" ของหน่วยงาน แล้วกดบันทึก — ไม่ต้องสร้างแยก

**เพิ่มมิติ?** ④ ตั้งค่า → มิติ → **+ เพิ่มมิติ** → แก้ชื่อ → บันทึก จากนั้นเลือกมิตินี้ในตัวชี้วัดได้

**เพิ่ม/แก้ตัวชี้วัด หรือเติมเป้าหมาย?** ④ ตั้งค่า → ตัวชี้วัด → กดดินสอ หรือ + เพิ่มตัวชี้วัด — ช่องเป้าหมายจะแสดงทันทีว่าระบบตีความเป็นเกณฑ์อะไร (เช่น "ผ่านเมื่อผล ≥ 80")

**คนอื่นเปิดโค้ดใน GitHub ได้ จะปลอดภัยไหม?** ค่าใน `config.js` เป็นแค่ที่อยู่โปรเจกต์ ไม่ใช่รหัสผ่าน การอ่าน/เขียนข้อมูลถูกควบคุมโดย `database.rules.json` บนเซิร์ฟเวอร์ — คนที่ไม่มีอีเมลในระบบจะอ่านหรือแก้ข้อมูลไม่ได้ และ editor แก้ได้เฉพาะวอร์ดตัวเอง แม้จะแก้โค้ดฝั่งเบราว์เซอร์ก็ตาม เวลาบันทึกใช้เวลาจากเซิร์ฟเวอร์ ปลอมไม่ได้

**ข้อมูลจะเต็มไหม?** แผนฟรี (Spark) ได้ 1 GB เก็บข้อมูล / 10 GB ต่อเดือนสำหรับดาวน์โหลด — ระบบนี้ใช้ราว 1–3 MB ต่อปี ใช้ได้หลายสิบปี

**สำรองข้อมูล?** ④ ตั้งค่า → นำเข้า / ส่งออก → **ดาวน์โหลด Excel** (ข้อมูลพื้นฐาน + ผลงาน + Log ของปีที่เลือก) แนะนำทำทุกสิ้นเดือน

**ล็อกอินแล้วขึ้น "unauthorized-domain"** → ทำขั้นที่ 1 ข้อ 4 ให้ตรงกับโดเมนที่เปิดอยู่

**ล็อกอินแล้วขึ้น "ยังไม่ได้รับสิทธิ์"** → ผู้ดูแลยังไม่ได้เพิ่มอีเมลนี้ หรือพิมพ์อีเมลไม่ตรงกับบัญชี Google ที่ใช้ล็อกอิน

## โครงสร้างข้อมูลใน Realtime Database

```
meta/wards/{wid}            ชื่อหน่วยงาน กลุ่มงาน ลำดับ
meta/dims/d{รหัส}           ชื่อมิติ
meta/kpis/{KPI_ID}          ข้อมูลตัวชี้วัด + หน่วยงานที่ใช้
results/y{ปีงบ}/{wid}/m01…m12/{KPI_ID}   ผลงาน (m01 = ต.ค. … m12 = ก.ย.) + ผู้บันทึก + อีเมล + เวลา
log/y{ปีงบ}/{id}            ประวัติ เพิ่ม/แก้ไข/ลบ พร้อมค่าเดิม (แก้หรือลบประวัติไม่ได้)
users/{อีเมลแทน . ด้วย ,}   สิทธิ์ผู้ใช้
```

## ซิงก์สองทางกับ Google Sheet (ไม่บังคับ)

ไฟล์ `FirebaseSync.gs` วางใน Apps Script ของไฟล์ชีต (ส่วนขยาย → Apps Script) — **ไม่ต้องอัปโหลดขึ้น GitHub**
แก้แท็บ KPI / Wards / มิติ ในชีต หรือแก้ในหน้าเว็บ → อีกฝั่งอัปเดตเองภายใน ~1 นาที

1. บัญชีที่จะติดตั้งต้องเป็นสมาชิกโปรเจกต์ Firebase (Project settings → Users and permissions → Add member → Editor)
2. วางโค้ดใน Apps Script ไฟล์ใหม่ชื่อ `FirebaseSync` → ใส่ `FBS_DB_URL` = databaseURL
3. Project Settings → ติ๊ก Show appsscript.json → เพิ่ม `oauthScopes`:
   `spreadsheets`, `script.external_request`, `script.scriptapp`, `script.container.ui`, `userinfo.email`, `firebase.database` (ขึ้นต้นด้วย `https://www.googleapis.com/auth/`)
4. เลือกฟังก์ชัน `fbsSetup` → Run → อนุญาตสิทธิ์ → เปิดชีตใหม่จะมีเมนู 🔄 Firebase

กติกา: ห้ามแก้คอลัมน์ `ward_id` · ชื่อใน "หน่วยงานที่ใช้" ต้องตรงแท็บ Wards (พิมพ์ผิด = ไม่ส่ง + เตือน) · แก้ตัวเดียวกันพร้อมกัน = ยึดเว็บ · ลบแถวในชีตจำนวนมาก (>5 และ >10%) = ไม่ลบใน Firebase · เปิดซิงก์แล้วห้ามใช้ปุ่มนำเข้า Excel ในเว็บ · สถานะดูได้ที่แท็บ "สถานะซิงก์"
